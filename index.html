HTTP Status Service

Returns an HTTP status response as plain HTML or JSON.

Try it

Routes

GET /html/{statuscode}?lang=xx
GET /json/{statuscode}?lang=xx
HEAD /html/{statuscode}?lang=xx
HEAD /json/{statuscode}?lang=xx

Examples: /html/502?lang=ja · /json/418?lang=fr

Response format

  • HTML contains an English status heading, a localized description, a link back here, and a creator link. It uses no CSS.
  • JSON contains status, an always-English message, and a localized description.
{"status":404,"message":"Not Found","description":"サーバーは要求されたリソースを見つけられません。"}

Languages

en, ja, de, es, fr, ko, pt-BR, and zh-CN are supported.

  • If lang is omitted, the service uses Accept-Language, then English.
  • An unsupported lang value silently falls back to English.
  • pt maps to pt-BR; zh and zh-Hans map to zh-CN.

Status behavior

  • The accepted range is 100 through 599. Registered reason phrases follow the IANA registry; unassigned values use Unassigned.
  • Descriptions are concise localized summaries based on MDN HTTP status documentation and the referenced standards.
  • 1xx responses are interim, not final. Where supported, 100, 102, or 103 is emitted first, followed by a final 200 response containing the requested status details.
  • 204, 205, 304, and all HEAD requests have no response body.
  • Responses are not cached. No authentication, cookies, or environment variables are used.

References: MDN HTTP response status codes · IANA HTTP Status Code Registry
